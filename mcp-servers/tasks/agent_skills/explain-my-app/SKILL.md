# Explain an app

## Steps

1. `list_my_apps`, then read the entry point and the main pieces.
2. Explain three things: what it does for whoever uses it, how it is put
   together, and where the important logic lives.
3. Name the files, so they can look themselves.

## Rules

- Lead with what it does for a person, not with the framework it uses.
- Plain words. Somebody asking what their app does is not asking for a
  dependency list.
- If something is genuinely unclear from the code, say it is unclear rather
  than inventing an explanation that fits.
